# CryptoPool PRO — Buyer Sales Package

**Release:** 9.0.0  
**Prepared:** 2026-09-04  
**Asset:** Web3 / DeFi product & technology asset  
**Current status:** Early-stage MVP / pre-revenue / Ethereum Sepolia testnet

## 1. Executive summary

CryptoPool PRO is a working Web3/DeFi software foundation for acquisition and further development. It gives a buyer an existing responsive frontend, wallet connection UX, live cryptocurrency market-data experience, charting, and an Ethereum Sepolia testnet transaction flow instead of requiring the entire product foundation to be built from zero.

The current product is deliberately positioned as an MVP/testnet technology asset. It is not represented as an audited production DeFi protocol, custody system, guaranteed-yield investment product, or revenue-generating business.

## 2. Product snapshot

- React 19 + Vite frontend
- Reown AppKit + Wagmi + Viem wallet integration
- Non-custodial wallet connection
- Ethereum Sepolia testnet support
- Public Sepolia ETH balance display
- User-authorized ETH transfer flow on Sepolia
- Transaction status and explorer verification
- Live market-data integration for supported assets
- Multi-timeframe charts
- Dashboard, Markets, Pools, Portfolio, Wallet and Trade views
- Responsive desktop/mobile interface
- GitHub Actions + GitHub Pages deployment
- Technical, security, IP and acquisition documentation

## 3. Buyer value proposition

The acquisition is primarily about reducing initial product-development time and acquiring an existing Web3 product foundation. A buyer can continue from the current working baseline rather than starting the frontend, wallet integration, market-data presentation and deployment workflow from scratch.

Potential development directions include production smart contracts/vaults, backend/indexing, authentication, monitoring, analytics, mainnet deployment, monetization and compliance/legal work. These are future development opportunities, not claims about current production functionality.

## 4. Commercial status

No financial, user, traffic or performance metric should be presented to a buyer unless it can be independently supported by evidence.

## 5. What is included in a proposed acquisition

The final transfer should be governed by a written asset schedule. Subject to that agreement, the package may include:

- Source code for the agreed release
- Web application and project configuration
- Deployment configuration and documentation
- Technical/security/acquisition documentation
- Agreed project branding and brand assets
- Other specifically listed project assets

Third-party libraries, APIs, wallet providers, fonts, icons and external services are not automatically transferred as seller-owned IP; their own licenses and terms continue to apply.

## 6. Due-diligence process

1. Buyer reviews the public demo and listing.
2. Seller answers high-level product and technical questions.
3. Serious buyer receives appropriate additional documentation.
4. Source-code review is provided in a controlled manner where appropriate.
5. Buyer and seller agree the exact asset/IP schedule.
6. Written acquisition/assignment agreement is completed.
7. Payment is secured through an appropriate marketplace or escrow mechanism where available.
8. Final repository, deployment and agreed assets are transferred according to the agreement.

The seller will not provide private keys, seed phrases, wallet credentials, unrelated account credentials, or other secrets.

## 7. Security position

The application is non-custodial and intended for testnet/demo use. Users authorize their own wallet transactions. Source maps are disabled in production builds, but browser-delivered JavaScript can still be inspected; this is not presented as source-code secrecy.

Production deployment would require additional independent security work appropriate to the final architecture, including smart-contract review/audit where applicable, backend security, monitoring, abuse controls and incident response.

## 8. IP and ownership

The seller intends to transfer only rights expressly identified in the final written agreement. Project-specific branding and original project materials are treated as seller-owned claims for transaction purposes, while third-party components remain subject to their respective licenses and rights.

No registered-trademark status is claimed unless supported by a valid registration record. The final agreement and asset schedule control the exact rights transferred.

## 9. Buyer FAQ

### Is this a production DeFi protocol?
No. The current release is an MVP/testnet technology asset. It is not represented as an audited production DeFi protocol.

### Does it currently generate revenue?
No. It is pre-revenue.

### Does it custody user funds?
No. The current wallet flow is non-custodial and user-authorized.

### Which blockchain is used?
Ethereum, currently configured for the Sepolia testnet.

### Can it be developed for mainnet?
Yes as a development direction, but mainnet production readiness requires additional engineering, security validation, deployment and legal/compliance work.

### What is the main acquisition thesis?
Acquire an existing Web3 product foundation and shorten the time needed to create a more complete commercial product.

## 10. Seller positioning

Recommended positioning: **Web3 / DeFi product and technology asset** rather than a revenue-generating business.

The seller should lead with the working product, technical foundation, integration work, documentation and development head start. Avoid unsupported claims about revenue, users, TVL, guaranteed returns, audits or production readiness.

## 11. Buyer qualification questions

Before providing deeper diligence, ask:

- What part of CryptoPool PRO is most relevant to your acquisition thesis?
- Do you have prior Web3/DeFi development or operating experience?
- Are you acquiring for an existing company, studio, or new product?
- What production scope do you intend to build after acquisition?
- What is your expected acquisition timeline?
- Are you prepared to complete reasonable identity/funds verification and written due diligence?

## 12. Negotiation principles

Evaluate offers on more than headline price:

- Payment security
- Buyer verification
- Exact IP and asset-transfer scope
- Whether source code and brand assets are included
- Post-sale support requested
- Closing timeline and certainty
- Marketplace/escrow fees
- Any continuing obligations

Do not accept an offer solely because it is the first offer. Do not transfer authoritative source or valuable credentials before the agreed transaction protections are in place.
