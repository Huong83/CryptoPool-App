# Buyer Handover Plan

## Phase 1 — Due diligence
- Provide source package and technical documentation.
- Buyer verifies build, deployment and wallet connection.
- Verify ownership of repository, domain, brand assets and other transferable assets.

## Phase 2 — Transaction closing
- Execute the final asset purchase / IP transfer agreement.
- Transfer only the assets explicitly listed in the agreement.
- Do not transfer personal wallet keys or unrelated personal accounts.

## Phase 3 — Technical transition
- Buyer creates a buyer-controlled GitHub organization/repository.
- Buyer creates a buyer-controlled Reown project and replaces the public Project ID in deployment configuration.
- Buyer configures GitHub Pages/domain settings.
- Buyer regenerates any required credentials and secrets.
- Buyer establishes production monitoring and security controls.

## Phase 4 — Production development
The buyer should treat the current package as an MVP foundation, not as production financial infrastructure. Production deployment should follow independent engineering, security, legal and compliance review.
